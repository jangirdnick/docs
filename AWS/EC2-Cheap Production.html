Cheap Production
Deployment Guide

Complete step-by-step production deployment of two Docker containers on a single EC2 instance using Nginx reverse proxy and free Let’s Encrypt SSL. Target cost: $17–20 / month.

Amazon Linux 2023 t3.small Docker Compose Nginx Let’s Encrypt No ALB
00
Final Architecture
What we are building
Core Idea

We run two Docker containers on one cheap EC2 instance. Nginx handles reverse proxy + SSL termination. Let’s Encrypt provides free HTTPS. No Application Load Balancer → big cost saving.

Internet Users │ ▼ Domain / Subdomains app.yourdomain.com → Frontend api.yourdomain.com → Backend API │ ▼ EC2 Instance (t3.small) ├── Nginx (Port 80 + 443) │ ├── Free SSL (Let’s Encrypt) │ ├── HTTP → HTTPS redirect │ ├── app.yourdomain.com → 127.0.0.1:8081 │ └── api.yourdomain.com → 127.0.0.1:8080 │ └── Docker Compose ├── App1 (Backend) → localhost:8080 └── App2 (Frontend) → localhost:8081
💡

Why no ALB? ALB costs ~$20–25/month alone. By putting Nginx on the same EC2 we keep the total bill under $20.

IAM Role & Security Group
Least privilege + correct ports

Create IAM Role (before launching instance)

IAM Console
  1. IAM → Roles → Create role
  2. Trusted entity: AWS service → EC2
  3. Permission: attach AmazonSSMManagedInstanceCore
  4. Role name: EC2-SSM-Role (or any name)
  5. Create role
💡

This role allows you to connect via Session Manager without opening SSH port permanently.

Install Docker Compose Plugin
Amazon Linux 2023 does not ship the plugin by default
⚠️

dnf install docker-compose-plugin fails on Amazon Linux 2023. Install the binary manually.

Commands
sudo mkdir -p /usr/local/lib/docker/cli-plugins

sudo curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-$(uname -m) \
  -o /usr/local/lib/docker/cli-plugins/docker-compose

sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-compose

docker compose version
07
App Folder, .env & docker-compose.yml
Secure and production-ready
Create folder
Commands
sudo mkdir -p /opt/app
sudo chown $USER:$USER /opt/app
cd /opt/app
Create .env
/opt/app/.env
# Backend
APP1_IMAGE=your-registry/backend:1.0.0
APP1_PORT=8080

# Frontend
APP2_IMAGE=your-registry/frontend:1.0.0
APP2_PORT=8081

TZ=UTC
COMPOSE_PROJECT_NAME=prod
Permissions
chmod 600 .env
Create docker-compose.yml
/opt/app/docker-compose.yml
version: "3.8"

services:
  app1:   # Backend
    image: ${APP1_IMAGE}
    container_name: app1
    restart: unless-stopped
    env_file: .env
    ports:
      - "127.0.0.1:8080:8080"   # only localhost
    networks:
      - app-network
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "5"

  app2:   # Frontend
    image: ${APP2_IMAGE}
    container_name: app2
    restart: unless-stopped
    env_file: .env
    ports:
      - "127.0.0.1:8081:8081"
    networks:
      - app-network
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "5"

networks:
  app-network:
    driver: bridge
💡

Binding to 127.0.0.1 means containers are not directly reachable from the internet. Only Nginx can talk to them.

Let’s Encrypt SSL (Certbot)
Free HTTPS certificates
Install Certbot
Command
sudo dnf install -y certbot python3-certbot-nginx
Temporary Nginx config (before certificates exist)
/etc/nginx/conf.d/apps.conf
server {
    listen 80;
    server_name app.yourdomain.com api.yourdomain.com;

    location / {
        return 200 'Nginx is working. Ready for SSL.';
        add_header Content-Type text/plain;
    }
}
Reload
sudo nginx -t
sudo systemctl restart nginx
Issue certificates
Command
sudo certbot --nginx -d app.yourdomain.com -d api.yourdomain.com

When asked:

  • Enter email
  • Agree to Terms → A
  • Redirect HTTP to HTTPS → choose 2
✅

Certificates are stored under /etc/letsencrypt/live/ and auto-renewal is configured.

12
Final Nginx Configuration
Reverse proxy to the two containers
/etc/nginx/conf.d/apps.conf
# HTTP → HTTPS Redirect
server {
    listen 80;
    server_name app.yourdomain.com api.yourdomain.com;

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

# Frontend → Port 8081
server {
    listen 443 ssl;
    http2 on;
    server_name app.yourdomain.com;

    ssl_certificate     /etc/letsencrypt/live/app.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.yourdomain.com/privkey.pem;
    include             /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam         /etc/letsencrypt/ssl-dhparams.pem;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 90;
    }
}

# Backend API → Port 8080
server {
    listen 443 ssl;
    http2 on;
    server_name api.yourdomain.com;

    ssl_certificate     /etc/letsencrypt/live/api.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.yourdomain.com/privkey.pem;
    include             /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam         /etc/letsencrypt/ssl-dhparams.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 90;
    }
}
Apply config
sudo nginx -t
sudo systemctl reload nginx

Troubleshooting
Common issues we faced and how to fix them
ProblemCauseFix
SG name invalid (sg-*) Name cannot start with sg- Use name like ec2-prod-nginx
docker-compose-plugin not found Not in Amazon Linux 2023 repos Install binary manually from GitHub
Permission denied on .env Wrong ownership sudo chown -R $USER:$USER /opt/app
nginx cannot load certificate Certbot not run yet Use temporary HTTP-only config first, then run certbot
Certbot NXDOMAIN DNS A records missing Create A records pointing to EC2 Public IP
unexpected end of file in nginx Missing closing } Delete file and rewrite clean config
502 Bad Gateway Container not running or wrong port docker compose ps + check proxy_pass ports
